# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

NoodlePaint is a standalone iPhone painting PWA: Vite + strict TypeScript + Canvas2D, with no runtime dependencies. It is deployed to GitHub Pages at https://zymsys.github.io/noodlepaint/ (repo zymsys/noodlepaint). README.md describes the gesture contract and install flow, DESIGN.md the visual intent (palette, 48px targets, single bottom tray), and QA.md the last verification run and what is still untested on a physical iPhone.

## Commands

Node 22.12+ or 24.

- `npm run dev`: Vite dev server on 127.0.0.1; `npm run dev:lan` exposes it on the LAN (no service worker on iOS over HTTP)
- `npm run phone`: build and serve the production PWA over LAN HTTPS at `https://vics-macbook-pro.local:4173/` (mkcert cert in gitignored `.certs/`; the iPhone trusts the mkcert root CA). Keep it running, `npm run build` in another terminal, then foreground the app to test the update path.
- `npm run release`: tests, `npm version patch`, push the tag. **Only tags deploy** to Pages; pushes to `main` just run CI.
- `npm test`: unit tests (`tsx --test tests/*.test.ts`, node:test + `fake-indexeddb`)
- Single test: `npx tsx --test --test-name-pattern='width is deterministic' tests/engine.test.ts`
- `npm run build`: `tsc --noEmit`, then `vite build`, then `scripts/sw-build.mjs` (writes `dist/sw.js`). TypeScript errors fail the build.
- `npm run test:browser` (`node scripts/browser-qa.mjs`): Playwright end-to-end checks. **Run `npm run build` first**, because it serves `dist/` on :4178 for the service-worker and offline checks, and also starts a Vite dev server on :4177. It never downloads browsers. Instead it uses hard-coded executables under `~/Library/Caches/ms-playwright/` (`chromium-1234`, `webkit-2336`), and Chromium can be overridden with `CHROME_PATH`. Its screenshots (main screen, mixer, menu, layers, library) go to `test-results/`.
- `scripts/icons.mjs` renders the `public/icon-*.png` files with the same Chromium.

## Architecture

- `src/engine.ts`: pure, DOM-free state machine and the core of the app. `Drawing` v2 is a fixed 900×1600 world with a stack of `layers` (each with `visible`, `locked`, `opacity`, `blend` (a canvas composite op), `strokes` of `{x,y,w}` samples, optional `erase` flag, and an optional photo `image` reference), plus `active` layer, cursor and colour. `migrate()` lifts v1 single-stroke-list drawings, and `validate()` is the single gate for anything read from IndexedDB or a backup.
  - Pointer roles: the first touch becomes `steer` and moves the cursor by relative deltas divided by the render scale. A second touch becomes `pressure`: it begins a stroke, and its vertical travel past `WIDTH_DEADZONE` changes width at `WIDTH_RATE` (clamped to 2–120). Mouse and pen draw with a single pointer. Lifting `steer` while `pressure` stays down is a clutch: the stroke stays open and the next touch becomes the new `steer` (relative, so no jump). Otherwise `blocked` stops a leftover contact from taking over after the steering contact lifts.
  - View: a second touch landing within `TAP_SPREAD` of the first sets `navigating` instead of painting. Pinch and drag change `view` (zoom 1–`MAX_ZOOM` about the fingers' midpoint, pan clamped so the paper always covers the screen) until every finger lifts, then `endNavigation()` pulls an off-screen cursor into view. `transform` (scale/ox/oy from `viewport` + `view`) is the single world-to-canvas mapping that the renderer and pointer scaling use. A quick, still simultaneous tap still undoes.
  - Undo: every undoable change goes through `edit()` or `begin()`, which push a `Snapshot` (copied layer records and stroke lists, shared immutable strokes) onto `history` and clear `future` (redo). Continuous adjustments pass `undoable=false` after their first step.
  - Taps: when timestamps are passed to `downPointer`/`upPointer`, a quick 2-finger tap undoes and a 3-finger tap redoes (`TAP_*` constants). The dot the tap itself painted is retracted first, and the redo stack it would have cleared is restored. Without timestamps (most unit tests) taps are never detected.
- `src/render.ts`: per-layer caches and the composite are screen-sized and painted through `engine.transform`, so zoom stays sharp; any view change repaints every layer. While `navigating`, it stretches a frozen copy of the last composite over a whole-paper preview instead of repainting per frame.
- `src/main.ts`: DOM wiring. It translates PointerEvents (including `getCoalescedEvents` and `timeStamp`) into engine calls, and calls `engine.suspend()` whenever a gesture must end safely: on cancel, lost capture, resize, a touch outside the canvas while painting, or blur. It also wires the tray (inks, eraser, undo, layers, ⋯), the sheets (`#menu`, `#library`, `#layers`, `#panel` help, `#mixer`), saving, Save to Photos, backups, photo import and the service-worker "Update app" flow. `showLayers()` only rebuilds when the layer stack changes, because a rebuild between a tap's pointerdown and its click swallows the tap. In dev builds it exposes `window.__noodlepaint = {engine, renderer, queue, store, doc}`, which the browser QA script depends on.
- `src/storage.ts`: IndexedDB `noodlepaint` v2 has the stores `docs` (one `Doc` per drawing), `cards` (library name, date and thumbnail, so listing never loads strokes), `meta` (`current` doc id) and `blobs` (photo pixels keyed `<docId>/<id>`, deleted by key range along with their drawing). The v1→v2 upgrade moves the old `sketch` record into the library; invalid old data aborts the upgrade and is left untouched. `SaveQueue` serializes whole-`Doc` writes and only advances `savedRevision` after a transaction commits. Saving copies the whole drawing on the main thread, so it never runs while any finger is down (a stall there turns the next movement into one straight jump): checkpoints happen every 500 ms while dirty and no pointers are down, when the last finger lifts, and at `pagehide`/`visibilitychange`. `engine.snapshot()` shares finished strokes and copies only the active one. If the initial read fails, `loadFailed` blocks all writes so existing data is never overwritten. Before switching or deleting the open drawing, main flushes its saves so no in-flight write can resurrect it.
- `src/backup.ts`: backups are `{app:'noodlepaint',version:2,docs:[{name,drawing,images}]}` with photos as data URLs. Restoring always adds new library entries with re-keyed photos, and plain v1/v2 drawing JSON is accepted too.
- `src/palette.ts` and `src/mixer.ts`: the four ink swatches are user-editable. Tap selects; a 450 ms press-and-hold (or `contextmenu`) opens the `#mixer` dialog (HSV shade pad, hue range, and Pick, an eyedropper overlay that samples the composed painting). The mixer ignores clicks for a moment after opening, because the long-press finger lifts over its buttons. `palette.ts` is pure (hex↔HSV, validated parse) and unit-tested. Swatch colours persist in `localStorage` (`noodlepaint-palette`) as a per-device convenience that falls back to defaults on any failure. The active stroke colour lives in the `Drawing`, so it must stay lowercase `#rrggbb` to pass `validate()`.
- `src/render.ts`: fits the world into the canvas without stretching (`scale`/`ox`/`oy`). Each layer has its own paper-sized pixel canvas, updated incrementally while a stroke grows (erase strokes use `destination-out`) and repainted when its stroke list or photo changes. Layers are composited onto `comp` with their opacity and blend, and the cursor ring is drawn on top (dashed for the eraser). `sample()` reads `comp` for the eyedropper, `compose()` renders exports (`png()`, 2×) and library thumbnails, and photos decode lazily through `loadBlob`.
- `src/sw-template.js` → `dist/sw.js`: `sw-build.mjs` replaces `__VERSION__` with a content hash of the shell and `__SHELL__` with the asset list. The worker caches only the exact app shell (it rejects redirects and wrong content types so auth-gate pages never get cached), serves navigations network-first, and waits for an `ACTIVATE` message instead of auto-activating. Don't add `skipWaiting` or automatic reloads, because an update must never land mid-stroke.
- All paths are relative (`base: './'` in `vite.config.ts`, `./manifest.webmanifest`, `./sw.js`, scope `./`) because Pages serves the app under `/noodlepaint/`. Never introduce root-absolute URLs.
- Deploy: `.github/workflows/pages.yml` runs on `v*` tags (`npm ci`, `npm test`, `npm run build`, then upload `dist/`). Installed apps call `registration.update()` when they return to the foreground and show a dot on the tray's ⋯ button (`#more[data-badge]`: `update` or `alert`). The `#status` text is visually hidden, but tests still read it. `__APP_VERSION__` (from `vite.config.ts`) is shown in Help; local builds are tagged `-local (sha)`.

## Conventions

- Source is written in a dense, semicolon-joined style with very few comments. Match it when editing.
- Keep gesture behaviour in `engine.ts` so it stays unit-testable without a DOM. Gesture and storage invariants (no cursor jump on first down, role retention, safe cancellation, and never writing after a failed load) each have a test. Update the test alongside any behaviour change.
