# NoodlePaint

A Vite + TypeScript + Canvas2D two-finger painting PWA for iPhone. Live at https://zymsys.github.io/noodlepaint/.

One touch steers by relative client-coordinate deltas. A second touch lowers the brush and changes width once its vertical travel passes a 24px dead zone (so a resting finger’s drift never resizes), then by −0.15 world units per vertical world unit; `WIDTH_DEADZONE`/`WIDTH_RATE` in `src/engine.ts`. Width is clamped to 2–120. Tap the width number at the bottom of the canvas to set it exactly (logarithmic slider, ±1 buttons, a preview at the current zoom) and to lock it; a locked width ignores the second finger, wheel and keys, and the lock is remembered on the device. New users can tap “Try the tutorial” on the empty canvas (or ⋯ → Tutorial): a coach card waits for each real gesture (steer, paint, size, two-finger undo), then lists the other features. Tap a swatch to pick an ink; press and hold (or right-click) a swatch to mix a new colour for it. Tap two fingers to undo and three to redo. The eraser sits beside the inks. The tray's layers button manages up to 20 layers (visibility, lock, opacity, blend mode, order, photo layers from Photos or the camera), and the ⋯ menu holds New drawing, Library, Save to Photos (2× PNG via the share sheet), Redo, Clear canvas, backups and Help. The mixer's Pick button is an eyedropper. Pointer IDs retain roles; a held extra contact never takes over. If the steering contact lifts while the painting contact stays down, the stroke waits: put a finger down anywhere and keep steering the same line (like lifting a mouse). If it lifts with no painting contact, all remaining contacts must leave before another gesture. Two fingers landing together (within 150 ms) pan and zoom instead of painting (up to 10×; pinch out to fit); Ctrl+wheel or a trackpad pinch zooms on desktop. Pressure lift leaves the driver hovering. Cancellation, capture loss, backgrounding, resize and controls end the current stroke safely.

Artwork has fixed 900×1600 coordinates, fitted without stretching. Each drawing (layers, editable x/y/width samples, colour; photos as separate blobs) is stored in an IndexedDB library, including active checkpoints every 500 ms and immediate stroke-end/lifecycle checkpoints. Save state advances only after a committed transaction. A failed initial read locks out writes to protect existing data; backups can be exported/imported. Abrupt process termination can still lose work since the last committed checkpoint. Undo/redo is session-local and covers strokes, clears and layer changes; the last 100 restored strokes can be undone individually. Clear is undoable. Restoring a backup adds its drawings to the library and never replaces existing ones.

## Develop
Use Node 22.12+ or 24. `npm ci`, `npm test`, `npm run build`, `npm run dev`. Build emits a revisioned service worker and relative manifest/scope. No browser download is required: point tests at existing browser executables. `npm run build` runs TypeScript first. Vite uses `base: './'`, so the build works under any sub-path.

Phone testing: `npm run dev:lan` serves the dev build on the LAN (UI only; iOS refuses service workers over plain HTTP). `npm run phone` builds and serves the production PWA at `https://<bonjour-name>.local:4173/` for on-device install/update testing, using an mkcert certificate in `.certs/` (gitignored; the script prints the command to create it). One-time phone setup: open the `:4174` link it prints to download the dev root CA, install the profile, then enable full trust under Settings → General → About → Certificate Trust Settings. Rebuild with `npm run build` while it runs, then foreground the app to receive the update. Help → Version shows `x.y.z-local (sha)` for local builds.

## Release
`npm run release` runs the tests, bumps the patch version, and pushes a `v*` tag; `.github/workflows/pages.yml` then builds and publishes `dist/` to GitHub Pages. Pushes to `main` only run CI (`ci.yml`). Each build gets a new content-hashed service worker, so installed apps pick up the update in the background.

## Install
Open https://zymsys.github.io/noodlepaint/ in iPhone Safari. Share (or More, then Share) → Add to Home Screen → enable Open as Web App if shown → Add. Launch the installed app online and wait for Offline ready in Help. Safari and standalone storage may be separate; use Save editable backup / Open backup to transfer a drawing. Browser storage can be evicted. Offline readiness requires a controlling worker and a complete app-shell cache, checked separately per installation.

Updates cache a new shell and wait. The app checks for one whenever it returns to the foreground; a dot appears on the ? button in the tray, and Help’s Update app button saves first, then deliberately activates and reloads. No automatic reload midstroke. Drawings live in a separate IndexedDB database and survive updates. Device cold launch must be verified on actual iPhone.

## Validation
28 unit tests cover the gesture engine, corruption validation, IndexedDB, save serialization and colour/palette maths. `node scripts/browser-qa.mjs` uses already installed Chromium/WebKit (override CHROME_PATH if needed); it covers real browser-dispatched simulated touch contacts, mouse, keyboard, resize, storage failure, offline shell, delayed worker updates, auth redirect rejection and the swatch mixer (tap vs. hold, cancel, persistence, reset). These are desktop browser simulations, not physical iPhone validation.

Primary iPhone references: https://webkit.org/blog/14787/webkit-features-in-safari-17-2/ (installation copies cookies, not other local storage); https://webkit.org/blog/14403/updates-to-storage-policy/ (quota/eviction and persistence); Apple iPhone Safari Add to Home Screen guidance.
